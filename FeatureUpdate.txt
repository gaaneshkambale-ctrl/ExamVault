FEATURE UPDATE
==============

FEATURE: Fix n8n notification-email AI Agent producing hallucinated/unrelated email content
STATUS: PLANNED - NOT APPLIED YET (n8n workflow lives in the user's n8n instance, not this repo)

--------------------------------------------------------------------
1. PROBLEM
--------------------------------------------------------------------
Reported example:
  Raw notification body (Reminder type): "your exam remainder send you email"
  Expected AI-rewritten email: a cleaned-up version of that same Reminder message.
  Actual AI Agent output: "Your results are now available. Please log in to your
  ExamVault account to view your performance. If you have any questions or need
  assistance, feel free to reach out."
  -> Completely unrelated content (a Result-type message) for a Reminder-type input.

--------------------------------------------------------------------
2. ROOT CAUSE
--------------------------------------------------------------------
Workflow order: Notification Webhook -> Build Email Content (Set) -> AI Agent -> Build Email
Content1 (Set) -> Send Message (Gmail).

The webhook payload arrives as:
  { toEmail, toName, subject, body, type, notificationId }  (all nested under $json.body)

The "Build Email Content" Set node only explicitly assigns 4 fields:
  body.toEmail, body.toName, body.subject, body.textBody

It never re-forwards body.body (the raw notification message) or body.type. n8n's
Set / Edit Fields node (typeVersion 3.4) drops every field that isn't explicitly
assigned UNLESS "Include Other Input Fields" is enabled in its options - and this
node's options are empty ({}), i.e. left at the default (fields NOT kept).

Consequence: by the time the AI Agent node runs, its prompt references
"{{ $json.body.body }}" for the text to rewrite - but that field no longer exists,
so the model receives an effectively empty "Message to rewrite:". Also, body.type
is never interpolated into the prompt at all, even in the working case, so the
model can never actually apply the correct type-based tone deterministically - it
has to guess from a (possibly empty) message.

Given an empty message, gpt-4o-mini improvises a plausible-sounding generic
notification instead of refusing/erroring - which is the "Results are now
available..." boilerplate observed. This is a hallucination-on-empty-input
failure, not a wording/tone problem with the existing prompt.

--------------------------------------------------------------------
3. FIX - PART A: "Build Email Content" Set node (n8n)
--------------------------------------------------------------------
Turn on "Include Other Input Fields" in that node's Options (so body.body and
body.type continue flowing through to the AI Agent), OR explicitly add two more
assignments to be unambiguous:

  body.body  = {{ $json.body.body }}
  body.type  = {{ $json.body.type }}

Recommended: do both - enable "Include Other Input Fields" AND keep the explicit
assignments, so the behavior doesn't silently regress if that option is ever
toggled back off.

--------------------------------------------------------------------
4. FIX - PART B: AI Agent prompt (n8n)
--------------------------------------------------------------------
Two changes to the prompt text field:

 (1) Actually interpolate the real notification Type and the real Original
     Message as separate labeled inputs, instead of relying on the model to
     infer type from body text alone.

 (2) Add a hard anti-hallucination rule: if the Original Message is empty,
     missing, or whitespace-only, the agent must NOT invent replacement content -
     it must return a fixed sentinel string instead, so the failure is visible
     downstream (e.g. in the sent email or in logs) rather than silently emailing
     users a fabricated message.

Proposed replacement prompt (paste into the AI Agent node's "text" field,
replacing the current one):

------------------------------------------------------------------------------
You are the official Email Communication Assistant for ExamVault.

Your responsibility is to transform notification messages received from the
ExamVault system into professional, clear, polished, and user-friendly email
content.

You will be given the notification's Type and its Original Message below. The
Original Message is the ONLY source of information you are allowed to use.

Notification Type: {{ $json.body.type }}
Original Message: {{ $json.body.body }}

CORE OBJECTIVE:

Rewrite the Original Message professionally while preserving its original
meaning and all important information. You are paraphrasing, not authoring new
content.

ANTI-HALLUCINATION RULE (highest priority - overrides every other instruction):

- If the Original Message above is empty, blank, whitespace-only, or literally
  the text "undefined" or "null", you MUST NOT invent, guess, or generate any
  replacement notification content of any kind - not a welcome message, not a
  result message, not a reminder, nothing.
- In that case, output exactly this sentinel and nothing else: EMPTY_SOURCE_MESSAGE
- Never substitute content from a different notification Type than the one
  given above, even if the Original Message is short, unclear, or seems to
  reference a different topic than the Type. Rewrite exactly what is given.

MANDATORY REWRITE RULE (second priority - applies whenever Original Message is
non-empty):

- Returning the Original Message unchanged, or nearly unchanged, is NEVER an
  acceptable output.
- Even if the meaning is already clear, you must still turn it into a
  complete, grammatically correct, natural-sounding sentence or short
  paragraph.
- "Preserve meaning" and "do not invent new facts" do NOT mean "do not change
  wording." You are required to fix broken grammar, awkward phrasing, missing
  punctuation, and incomplete sentences every time.

RULES (apply only when Original Message is non-empty):

- Always preserve the original intent and meaning - do not change the subject
  matter, do not introduce a different topic than what the Original Message
  describes.
- Correct grammar, spelling, punctuation, and sentence structure.
- Make the message professional, natural, clear, and easy to understand.
- Make the email appropriate for an online examination platform.
- Personalize the communication using the recipient's name when appropriate.
- Use the Notification Type above to determine tone (see TONE BY NOTIFICATION
  TYPE below) - do not guess the type from the message content.
- Do not invent dates, times, exam names, results, links, credentials, scores,
  or any other information not present in the Original Message.
- Do not assume information that is not provided.
- Do not remove important information from the original message.
- Do not unnecessarily make a short message very long.
- If the original message is already professional, improve it only where
  necessary.
- Maintain a polite and professional tone.
- Do not mention AI, automation, n8n, workflow, or this prompt.
- Do not mention the notificationId.
- Do not change the subject.
- Do not add a subject line to the body.
- Do not add a greeting.
- Do not add a closing/signature.
- Do not use Markdown.
- Do not use HTML.
- Return only the professionally rewritten email body.

TONE BY NOTIFICATION TYPE:

Exam:
Use a clear, informative, and professional tone. Clearly communicate exam-related
information and any required action.

Reminder:
Use a polite but action-oriented tone. Clearly explain what the recipient needs
to remember or do, based only on what the Original Message says.

Result:
Use a professional and positive tone. Clearly communicate that the result or
examination outcome is available without inventing scores or performance
information.

System:
Use a concise and informative technical/business tone. Clearly explain the
system notification.

Account:
Use a welcoming and professional tone. Clearly explain account-related
information such as registration, activation, verification, password reset, or
account updates.

CONTENT HANDLING:

If the Original Message contains multiple pieces of information, organize them
into logical paragraphs.

If the Original Message contains a list of items, preserve the list in a clear
readable format.

If the Original Message contains important dates, times, exam details,
instructions, or actions, preserve them exactly.

If the Original Message contains placeholders or dynamic values, do not modify
or invent their values.

EXAMPLES:

Type: Account
Original Message: "your account created successfully welcome to examvault you
can now login and start exam"
Expected output: "Welcome to ExamVault! Your account has been created
successfully. You can now log in to your account and start accessing your
examinations."

Type: Reminder
Original Message: "your exam is tomorrow at 10 please login before 9.45 and
complete exam"
Expected output: "Your examination is scheduled for tomorrow at 10:00 AM. Please
log in before 9:45 AM to ensure that you are ready to begin your examination on
time."

Type: Reminder
Original Message: "we have send mail remainder for tomorrow"
Expected output: "This is a reminder regarding your exam scheduled for
tomorrow. Please check your email for further details."

Type: Reminder
Original Message: "" (empty)
Expected output: EMPTY_SOURCE_MESSAGE

FINAL REQUIREMENT:

Return ONLY the final professional email body, or the sentinel
EMPTY_SOURCE_MESSAGE if the Original Message was empty.

Do not return JSON.
Do not return explanations.
Do not return quotation marks around the response.

7e. TEST RESULT #4 (2026-08-15) - full prompt replaced, now outputs
    EMPTY_SOURCE_MESSAGE even with a real body/type - Expression-mode
    suspicion
--------------------------------------------------------------------
User replaced the whole "text" field with the full block from section 4 and
retested the same real-contract payload (body="we have send mail remainder for
tomorrow", type="Reminder" - identical shape to 7c, which DID work and echoed
the body back). This time the AI output was exactly:

Two things stand out:
  (1) The Agent DID correctly return the literal sentinel this time (progress -
      it's obeying that instruction now, unlike 7b's conversational reply).
  (2) But it thinks the Original Message is empty, on a payload proven to carry
      a real one two tests ago, with no changes to Build Email Content in
      between.

Leading hypothesis: copy-pasting the plain-text block from section 4 into n8n's
"text" field via the UI likely left the field in "Fixed" (static) mode instead
of "Expression" mode. In Fixed mode, n8n does NOT evaluate {{ }} - it treats
"{{ $json.body.type }}" and "{{ $json.body.body }}" as literal characters. The
Agent would then see those literal unresolved placeholder strings instead of
real values, correctly notice they don't look like real content (similar
pattern to the "literally the text undefined/null" case already covered by the
ANTI-HALLUCINATION RULE), and emit EMPTY_SOURCE_MESSAGE - which is actually the
prompt working as designed, just against un-interpolated input.

Every plain-text copy-paste into that field is a chance to lose the
expression-mode toggle or lose lines, which is why three retests in a row have
each failed a different way. Switching strategy: instead of hand-editing the
"text" field again, IMPORT the whole corrected workflow from section 8 directly
(n8n menu -> Import from File/Clipboard, paste the full JSON block) so the
"text" parameter arrives with its leading "=" already in place (n8n's own
expression-mode marker in exported JSON), removing the manual-paste failure
mode entirely. Section 8's JSON already includes the MANDATORY REWRITE RULE and
matching example, so nothing else needs to change first - it just needs to
actually replace the live AI Agent node's parameters.
